# URLを解説してObsidianに残す

リンクを渡されたら、**中身を実際に取得してから**解説する。タイトルや推測だけで語らない。

## 使うタイミング

- YouTube・X（旧Twitter）・記事などのURLと一緒に「解説して」「要約して」「これ何？」「まとめて」と言われたとき
- URLだけを貼られて、明らかに内容を知りたそうなとき

## 手順

### 1. 中身を取得する

```bash
/usr/bin/python3 <キットの配置先>/tools/fetch_url.py "<URL>"
```

- YouTube → タイトル・概要欄・字幕が返る
- X → 投稿の本文が返る（トークン未設定なら、その旨の案内が返る）
- その他のWebページ → 本文が返る

**取得に失敗したら**:
- 一般ページで失敗 → Claude Code内蔵のWebFetchで取り直す
- YouTubeで「yt-dlpが無い」 → 導入コマンドを案内する（`brew install yt-dlp`）
- Xでトークンが無い → 投稿本文を貼ってもらう。**勝手に推測で解説しない**
- 字幕が無い動画 → その事実を伝え、概要欄とタイトルから読み取れる範囲に限って解説する

### 2. 解説する

取得した中身をもとに、次の構成で日本語で書く。**取得した内容と、あなたが補う背景知識は必ず区別する**。

1. **これは何か** — 1〜2文で
2. **要点** — 箇条書き3〜6個。数字・固有名詞は取得内容から正確に引く
3. **背景・周辺情報** — 前提となる技術や文脈、関連する動き。ここはあなたの知識で補う部分だと明示する
4. **この人にとっての意味** — 利用者の関心（Obsidianの `02_プロジェクト/` を見れば分かる）に照らして、使えそうな点・注意点
5. **確度** — 取得できなかった部分、推測で補った部分を正直に書く

### 3. Obsidianに保存する

`00_受信箱/` に次の形式で保存する。ファイル名は `YYYY-MM-DD_解説_{短いタイトル}.md`。

```markdown
---
record_type: research
project: general
status: active
created: YYYY-MM-DD
updated: YYYY-MM-DD
source: <URL>
tags: [解説, url]
---

# {タイトル}

（上の1〜5をそのまま書く）
```

受信箱に置いておけば、翌朝の自動整理がトピック別のwikiへ振り分ける。

## やらないこと

- 取得せずにURLの見た目だけで解説する
- 取得できなかったのに、できたふりをする
- 動画の字幕が無いのに、内容を知っているかのように書く
