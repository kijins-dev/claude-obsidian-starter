# Obsidian連携ルール（Claude Code用）

> このファイルを `~/.claude/rules/obsidian.md` に置き、`~/.claude/CLAUDE.md` から
> 「Obsidian操作時は `rules/obsidian.md` に従う」と1行参照させる。
> これがClaude CodeにVaultの「地図」を渡す仕組みの本体。

Vault = あなたの外部記憶。役割: (1) 判断の履歴 (2) 技術知見の再利用wiki (3) セッション間の記憶継続。

## Vaultパス
`/Users/あなたのユーザー名/Documents/あなたのVault名/` ← **実際のパスに書き換えること**

## 情報ルーティング決定木（MUST）

新しい情報を得たら、まずこの表で置き場所を決める:

| 情報の種類 | 置き場所 | 書き手 |
|---|---|---|
| セッションでやったこと（時系列） | `01_01_デイリーノート/{YYYY}年/` | **Stopフックが自動**。手動で書かない |
| 設計判断・却下した代替案・フェーズ進行 | `02_プロジェクト/{該当}/` | **Claude Codeが判断して書く** |
| 技術知見（API制限・ワークアラウンド・発見） | `04_技術ドキュメント/` | **毎朝の自動整理が生成**。直接書かない |
| 会議の議事録 | `05_会議記録/` | 人間・自動 |
| 未整理の一時情報 | `00_受信箱/` | 人間（自動整理が翌朝拾う） |
| 終了したプロジェクト・古いノート | `07_アーカイブ/` | 削除せずここへ移動 |

**迷ったときの3問**: (1) 人間が後で読み返す判断記録か? → `02_プロジェクト/` (2) 技術的な再利用知識か? → デイリーノートに書けば自動整理が拾う (3) 一時メモか? → `00_受信箱/`

## 3層構造（いつ書くか）

- **層1（自動）**: Stopフックが会話終了ごとにデイリーノートへセッション要約をupsert。何もしなくてよい
- **層2（自動）**: 毎朝05:00の自動整理（ingest）が前日デイリー+受信箱+Clippingsから `04_技術ドキュメント/` のwikiを自動生成。毎週月曜はリンク切れ・孤児ノートの点検レポートを `00_受信箱/` に出力
- **層3（Claude Codeが判断して書く）**: 大きな作業完了（機能実装・デプロイ・3ファイル以上の変更）や設計判断をしたとき、`02_プロジェクト/{名前}/` に記録する

## デイリーノートへの手動追記（マーカー厳守）
- 正パスは `01_01_デイリーノート/{YYYY}年/YYYY-MM-DD.md`。**直下に日付ファイルを作成しない**
- フックが管理する `<!-- session: {id} -->` 〜 `<!-- /session: {id} -->` の**中は編集しない**
- 追記はマーカーの**外側**に書く

## AI生成ノートのfrontmatter標準

Claude Codeが `02_プロジェクト/` に新規ノートを作る時は必ず付ける:

```yaml
---
record_type: decision | research | wiki | log | index
project: プロジェクト名
status: active | paused | inactive    # 英語小文字のみ（日本語statusはフィルタが壊れる）
created: YYYY-MM-DD
updated: YYYY-MM-DD                   # 日付のみ。コメント併記禁止
tags: []
---
```

## Obsidian記法（Vault書き込み時MUST）
- **内部リンクはwikilink**: `[[ノート名]]` / `[[ノート名|表示名]]`。外部URLのみ `[表示](url)`
- **存在しないノートへのリンクを乱造しない**（リンク切れの温床。実在するノートだけリンクする）
- コールアウト `> [!note]` / ハイライト `==〜==` / タグ `#tag` が使える

## 禁止事項
- Vaultルート直下への.md作成
- `04_技術ドキュメント/` への直接書き込み（自動整理の担当領域。明示指示時のみ可）
- フックのセッションマーカー内の編集
