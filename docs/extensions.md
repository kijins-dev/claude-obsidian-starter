# 応用編: このキットの先にあるもの

スターターキットは「土台」です。実際の運用では、ここにいろいろな自動化を足していけます。
以下は実運用されている拡張の実例です（このキットには含まれません。アイデア集として読んでください）。

## 1. 議事録の自動取り込み＋AI要約

AIボイスレコーダー（Plaud等）やオンライン会議の文字起こしを毎朝Vaultの `05_会議記録/` へ自動同期し、
さらに**文字起こし原文＋用語集をClaude APIに渡して自前の議事録を生成**する拡張。

ポイントは**用語集**。文字起こしは固有名詞（人名・商品名・社名）を頻繁に間違えるため、
「正しい表記のリスト」をプロンプトに埋め込むと議事録の品質が劇的に上がります。

## 2. 用語集を業務データベースから自動更新

用語集を手で育てるのは続きません。自社の業務システム（顧客管理・商品管理のDB）に
正式名称のマスターデータがあるなら、そこから**毎朝自動で用語集を再生成**できます。

- 用語集ファイルに `<!-- AUTO-GLOSSARY:START -->` 〜 `<!-- AUTO-GLOSSARY:END -->` のマーカーを置く
- 毎朝のスクリプトがマーカーの内側だけをDBの最新データで書き換える
- マーカーの外は手書きゾーンとして保護される

DBへは**読み取り専用**で接続し、失敗した朝は前日の用語集で続行（フェイルソフト）にするのが安全です。

## 3. 失敗通知（静かに死なせない）

自動化は「動かなくなったことに気づけない」のが最大の敵です。実運用では:

- 毎朝のジョブが失敗したらチャットツール（Slack/Chatwork等）へ通知
- フェイルソフトな処理（失敗しても全体は止めない設計）は「3日連続失敗で通知」のような遅延アラートを付ける
- 週次の点検レポート（リンク切れ件数の前週比など）もチャットに届ける

このキットではmacOS通知に留めていますが、チャット通知への差し替えは `run.sh` の通知部分を書き換えるだけです。

## 4. 他のAI・デバイスからの書き込み

Vaultはただのフォルダなので、Claude Code以外からも書けます。
Telegram経由のAIアシスタントの会話ログを `00_受信箱/` に書き出して同じ整理フローに乗せる、
モバイルからのメモをinboxに落とす、などが実例としてあります。
入口を何にしても「受信箱に入れれば翌朝整理される」という設計が効きます。

## 5. Vault自体のバックアップ

Vaultをgitリポジトリにして、毎晩「変更があればcommit＋GitHubのプライベートリポジトリへpush」する
launchdジョブを足すと、Macが壊れても外部記憶は無事です。push失敗時の通知もセットで。
